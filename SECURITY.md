# Security policy

This repository holds documentation (playbooks and role definitions). It contains no code that runs by itself and must contain no secrets.

## Report a problem
- **Leaked data** (a real name, phone number, email, booking reference, password or key): use GitHub's *Report a vulnerability* (private security advisory) under the Security tab. Do not open a public issue.
- **A rule that could cause a financial or customer harm** (for example, a step that would expose a supplier net price): open a normal issue using the "Safety concern" template.

## Handling
Reported leaks are removed from the files and from git history, and the affected value should be treated as compromised and rotated.
